1. Overview & Architecture

AlphaMarket is a SEBI-compliant advisory platform connecting registered investment advisors with brokers and distribution platforms. When an advisor publishes, modifies, or closes a trading recommendation (equity call or F&O position), we push structured data to your endpoint via secure HTTPS webhooks.

Key Principle: AlphaMarket's role ends at delivery. We push recommendation data to your endpoint. How you render, route, execute, or display the data is entirely your platform's responsibility. This is a data push integration — not trade execution.

What You Receive

Signed JSON payloads via HTTPS POST to your registered webhook endpoint. Each payload contains the full recommendation data — advisor details, strategy info, instrument data, entry/target/stop-loss prices, and exit data (on close events).

Detection Speed

Stop-loss and target price monitoring runs every 15 seconds during market hours (9:15 AM – 3:30 PM IST). When a trigger condition is met, the webhook fires within seconds. Advisor-initiated events (create, modify, close) fire instantly.

3. URL Whitelisting & Requirements

Your Webhook URL Must

  • Use HTTPS — HTTP endpoints are rejected. SSL certificate must be valid (Let's Encrypt is fine).
  • Be publicly accessible — AlphaMarket servers must reach your endpoint over the internet.
  • Accept POST with Content-Type: application/json.
  • Respond within 10 seconds — longer responses are treated as timeouts and retried.
  • Return 2xx for success — non-2xx triggers retries.

10. Duplicate Prevention

Per-Broker Duplicate Call Blocking

AlphaMarket prevents duplicate active calls from being sent to the same broker. When a new CALL_CREATED or POSITION_CREATED event is about to be dispatched:

  • Equity: If the same symbol already has an active (unclosed) call on that broker, the new call is blocked.
  • F&O: If the same symbol + strike combination already has an active position on that broker, the new position is blocked.

This is per-broker — the same symbol can exist on different brokers simultaneously. Different advisors recommending the same stock will result in only the first call being sent; subsequent ones are held until the first is closed.

Fail-open: If the duplicate check encounters an error, the call is sent anyway to avoid blocking legitimate recommendations.

Duplicate SL/Target Prevention

The scheduler re-checks the call/position status from the database before firing a close event. If a previous scheduler cycle already closed the position, the duplicate event is suppressed. This prevents the same SL or target from triggering twice.

11. MODIFY Event Handling

CALL_MODIFIED and POSITION_MODIFIED events always carry the same recommendationId as the original CALL_CREATED / POSITION_CREATED event. This allows brokers to match modifications to the original call without creating duplicate entries.

Modified fields typically include:

  • targetPriceRange / target — updated target price
  • stopLoss — updated stop-loss
  • duration — updated duration (if applicable)

All other fields remain identical to the original CREATE payload.

12. Profit & Loss Calculation

The profitLossPercent field is always populated on close events (CALL_CLOSED, POSITION_CLOSED, TARGET_ACHIEVED, STOPLOSS_TRIGGERED).

Calculation:

  • BUY calls: ((sellPrice - buyPrice) / buyPrice) × 100
  • SELL calls: ((buyPrice - sellPrice) / buyPrice) × 100

If the source system does not provide a percentage, it is calculated automatically from entry and exit prices.

Duration Field (Dreamstreet)

For brokers that require a duration field:

  • Intraday strategies: duration defaults to 1 day (factually correct by definition).
  • Non-intraday strategies: duration is set by the advisor. If not set, it will be null.

The durationUnit is always "days".

13. Security & Signature Verification

Signature Construction

PSEUDO// The signature is computed over the raw JSON body
signature = HMAC_SHA256(api_secret, raw_json_body)

// Compare with X-AlphaMarket-Signature header
// Use constant-time comparison to prevent timing attacks

Verification Rules

  • Timestamp freshness: Reject if X-AlphaMarket-Timestamp is older than 5 minutes. Prevents replay attacks.
  • Constant-time comparison: Use crypto.timingSafeEqual() (Node.js) or hmac.compare_digest() (Python). Never use ==.
  • Raw body: Compute signature over raw request body bytes, not parsed-and-re-serialized JSON.

Python Verification

Pythonimport hmac, hashlib, time

def verify_signature(request, secret):
    sig  = request.headers.get('X-AlphaMarket-Signature', '')
    ts   = request.headers.get('X-AlphaMarket-Timestamp', '')
    body = request.get_data()  # raw bytes

    # 1. Check timestamp freshness (5 min window)
    if abs(time.time() * 1000 - int(ts)) > 300000:
        return False

    # 2. Compute expected signature
    expected = hmac.new(
        secret.encode(), body, hashlib.sha256
    ).hexdigest()

    # 3. Constant-time comparison
    return hmac.compare_digest(sig, expected)

Node.js Verification

Node.jsconst crypto = require('crypto');

function verifySignature(req, secret) {
  const sig  = req.headers['x-alphamarket-signature'];
  const ts   = req.headers['x-alphamarket-timestamp'];
  const body = JSON.stringify(req.body);

  // Check timestamp (5 min)
  if (Math.abs(Date.now() - new Date(ts).getTime()) > 300000)
    return false;

  const expected = crypto
    .createHmac('sha256', secret)
    .update(body)
    .digest('hex');

  return crypto.timingSafeEqual(
    Buffer.from(sig), Buffer.from(expected)
  );
}

11. Receiver Implementation

Complete Node.js (Express) Receiver

Node.jsconst express = require('express');
const crypto = require('crypto');
const app = express();
app.use(express.json({ verify: (req, res, buf) => req.rawBody = buf }));

const SECRET = process.env.ALPHAMARKET_SECRET;
const seen = new Set();

app.post('/alphamarket/webhook', (req, res) => {
  const sig = req.headers['x-alphamarket-signature'];
  const ts  = req.headers['x-alphamarket-timestamp'];
  const evt = req.headers['x-alphamarket-event'];

  // 1. Verify timestamp
  if (Math.abs(Date.now() - new Date(ts).getTime()) > 300000)
    return res.status(401).json({ error: 'stale timestamp' });

  // 2. Verify HMAC signature
  const expected = crypto.createHmac('sha256', SECRET)
    .update(req.rawBody).digest('hex');
  if (!crypto.timingSafeEqual(Buffer.from(sig), Buffer.from(expected)))
    return res.status(401).json({ error: 'bad signature' });

  // 3. Deduplicate by recommendationId + event
  const dedupKey = req.body.data?.recommendationId + '_' + evt;
  if (seen.has(dedupKey))
    return res.json({ status: 'already_received' });
  seen.add(dedupKey);

  // 4. Route by event type
  const data = req.body.data;
  switch (evt) {
    case 'CALL_CREATED':
    case 'POSITION_CREATED':
      processNewRecommendation(data); break;
    case 'CALL_MODIFIED':
    case 'POSITION_MODIFIED':
      updateRecommendation(data); break;
    case 'CALL_CLOSED':
    case 'POSITION_CLOSED':
    case 'TARGET_ACHIEVED':
    case 'STOPLOSS_TRIGGERED':
    case 'TRAILING_SL_TRIGGERED':
      closeRecommendation(data); break;
  }

  res.json({ status: 'received' });
});

12. Retry Policy & Idempotency

Retry Schedule

If your endpoint returns non-2xx or times out, AlphaMarket retries with exponential backoff:

AttemptDelayCumulativeAction on Failure
1 (initial)Immediate0Retry
230 seconds30sRetry
32 minutes2m 30sRetry
410 minutes12m 30sMark as FAILED
4xx vs 5xx: We recommend returning 5xx for transient errors (will be retried) and 4xx only for permanent errors like bad signatures (will NOT be retried).

Idempotency

Use recommendationId + event type as a deduplication key. AlphaMarket may retry a delivery, so your handler should be safe to call multiple times for the same event. The recommendationId is unique and auto-incrementing.

17. Go-Live Checklist

Before going live, ensure your integration meets all requirements:

  • HTTPS endpoint with valid SSL certificate
  • HMAC-SHA256 signature verification implemented
  • Timestamp freshness check (5-minute window)
  • Deduplication by recommendationId + event type
  • Responds within 10 seconds
  • Returns 2xx for success, 4xx for permanent errors, 5xx for transient errors
  • Handles all event types (unknown events return 200, not error)
  • Parses both equityCall and fnoCall payloads correctly
  • String-typed prices in equityCall parsed correctly (targetPriceRange, stopLoss, profitGoal)
  • Test payload from AlphaMarket UAT received and processed successfully
  • API secret stored securely (env vars or secrets manager, not in code)
  • AlphaMarket outbound IP whitelisted (if firewall in use)
  • Monitoring / alerting set up for webhook failures
  • SEBI disclaimer displayed for advisory content
