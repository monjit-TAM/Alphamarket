1. Overview

AlphaMarket is a SEBI-registered investment advisory platform. Brokers integrate with AlphaMarket to receive trading recommendations (calls) published by advisors in real time, so that broker users can follow these advisors inside the broker's own app.

Two integration modes are available and both deliver the same payload shape:

ModeDirectionUse when
Pull APIBroker polls AlphaMarketScheduled reconciliation; broker-side control over timing; back-fill / replay of past calls
Webhook PushAlphaMarket POSTs to brokerReal-time delivery; production operations; event-driven architectures

Most production brokers use both: webhook for live delivery, Pull API for back-fill and reconciliation.

Base URLs

Production: https://alphamarket.co.in/api/v2
UAT: https://uat.alphamarket.co.in/api/v2

1.1 Scoping and visibility

Your broker account operates under scoping rules managed by AlphaMarket's integration team. You will only see data (calls, strategies, webhook events) that your account has been granted access to:

  • Advisors: you see calls only from advisors explicitly enabled for your broker.
  • Strategies: optional fine-grained filter — a specific list of strategies on top of the advisor filter. If empty, no strategy-level restriction applies (you see all strategies from enabled advisors).
  • Segments: equity vs F&O scoping. A broker can be configured for equity-only, F&O-only, or both. Codes: equity_cash, equity_intraday, equity_swing, equity_positional, fno_futures, fno_options.

Filters are intersected (AND semantics): for a call to be visible to you, its advisor AND its strategy (if strategy filter is set) AND its segment (if segment filter is set) must ALL be in your allowed lists.

Missing a strategy you expect? This is scope configuration, not a bug. Contact AlphaMarket admin to have it added to your allowed_strategies or allowed_advisors list. Turnaround is typically within hours.

2. Authentication

Every request to the Pull API must include your API key in the x-api-key header:

curl -H "x-api-key: amk_live_f387ae19154f71a6a95262dadd07184d6ee1115129987f5e" \
     https://alphamarket.co.in/api/v2/alpha/live-calls

Keys have the format amk_live_<64 hex chars>. Your paired apiSecret is used only for HMAC verification of inbound webhook deliveries — you never send it in requests.

Security. Your apiKey and apiSecret are credentials. Store them in environment variables, not in source code. Rotate them if exposed. Keys can be scoped to specific advisor IDs, strategies, segments, and IP ranges — contact hello@alphamarket.co.in to configure.

Obtaining a key

Contact hello@alphamarket.co.in with:

  • Broker name and primary contact email
  • Webhook endpoint URL (HTTPS only; must return 200-299 within 5 seconds)
  • Production IP ranges (for IP-whitelist configuration)
  • Whether you need access to all advisors or a subset

2.1 Rate limiting

Each broker account has a per-minute request cap enforced per api_key.

  • Default: 100 requests per minute
  • Window: rolling 60-second window, resets as requests age out
  • Configurable: contact AlphaMarket admin to raise the limit if your integration needs more (e.g. during bulk sync or aggressive polling). Limits of 500, 1000, or 10000 req/min are available on request.
  • Enforcement: requests over the limit receive HTTP 429 Too Many Requests with a Retry-After header
Tip: for polling integrations, start at 60-second intervals and monitor your 429 rate. Tight polling (every 5s or faster) on many endpoints can exhaust the default 100/min — ask us for a higher limit.

2.2 IP whitelisting

Optional but recommended: restrict API access to your production server IPs.

  • During onboarding, provide AlphaMarket admin with the public IPs your systems will call from (comma-separated; CIDR ranges not supported).
  • Effect: once set, requests from any other IP receive HTTP 403 Forbidden. An empty whitelist means all IPs are allowed.
  • Development: leave the whitelist empty during initial development/testing, then enable it before production cutover.
  • Changes: IP list changes are instant (no code deploy needed on our side) — admin updates the ip_whitelist column via the admin UI.
Not a substitute for API key security: IP whitelisting adds defense-in-depth. Still treat your api_key and api_secret as sensitive — leaked keys are a breach regardless of whitelist.

3. Response envelope

Every Pull API response and every webhook payload is wrapped in the same envelope:

{
  "status": "success",
  "statusCode": 200,
  "message": { "key": "GET", "message": "Get Successfully" },
  "data": { ... }
}

For list endpoints, data is an array and a total field is added at the top level:

{
  "status": "success",
  "statusCode": 200,
  "message": { "key": "GET", "message": "Get Successfully" },
  "data": [ {...}, {...}, ... ],
  "total": 42,
  "serverTime": "2026-04-16T18:45:00.123Z"
}

Errors follow the same shape with status: "error" and data: null:

{
  "status": "error",
  "statusCode": 401,
  "message": { "key": "UNAUTHORIZED", "message": "Invalid API key" },
  "data": null
}

4. Pull API — polling

The primary polling endpoint is GET /alpha/live-calls. It returns every active recommendation visible to your key.

GET /api/v2/alpha/live-calls

Recommended polling interval: 30-60 seconds. Use the serverTime in the response to do incremental polling — pass ?from=<prev serverTime> to /alpha/integration/call/search for changes since last poll.

Example — Node.js

const fetch = require('node-fetch');

const API_KEY = process.env.ALPHAMARKET_API_KEY;
const BASE = 'https://alphamarket.co.in/api/v2';

async function fetchLiveCalls() {
  const res = await fetch(`${BASE}/alpha/live-calls`, {
    headers: { 'x-api-key': API_KEY }
  });
  const body = await res.json();
  if (body.status !== 'success') throw new Error(body.message.message);
  console.log(`Received ${body.total} active calls`);
  return body.data;
}

// Poll every 45 seconds
setInterval(fetchLiveCalls, 45000);

Example — Python

import os, time, requests

API_KEY = os.environ['ALPHAMARKET_API_KEY']
BASE = 'https://alphamarket.co.in/api/v2'
HEADERS = {'x-api-key': API_KEY}

def fetch_live_calls():
    r = requests.get(f'{BASE}/alpha/live-calls', headers=HEADERS, timeout=10)
    r.raise_for_status()
    body = r.json()
    if body['status'] != 'success':
        raise RuntimeError(body['message']['message'])
    return body['data']

while True:
    calls = fetch_live_calls()
    print(f'Received {len(calls)} active calls')
    time.sleep(45)

5. Webhook push — real-time

When an advisor publishes, modifies, or closes a call (or the scheduler fires SL/target/trailing-SL events), AlphaMarket POSTs the event to your registered webhook URL:

  • Method: POST
  • Content-Type: application/json
  • Timeout: 5 seconds — return 2xx within this window
  • Retries: 3 attempts with delays 5s → 30s → 2min
  • User-Agent: AlphaMarket-Webhook/2.0

Headers sent

POST /your/webhook/path HTTP/1.1
Host: broker.example.com
Content-Type: application/json
User-Agent: AlphaMarket-Webhook/2.0
X-AlphaMarket-Event: CALL_CREATED
X-AlphaMarket-Signature: 8b1a9953c4611296a827abf8c47804d7abc012...
X-AlphaMarket-Timestamp: 2026-04-16T18:45:00.123Z

Response expected from your endpoint

Return HTTP 2xx (ideally 200 with an empty body or {"ok": true}) within 5 seconds. Anything else — non-2xx, timeout, connection error — triggers retry.

Idempotency. Every payload includes callId (a UUID). Use it as your idempotency key. If you receive the same callId + event combination twice (possible during retries), treat the second as a no-op.

5.3 Delivery, retries, and idempotency

AlphaMarket makes its best effort to deliver each event exactly once, but you should design for at-least-once semantics.

  • Timeout: we wait up to 10 seconds for your endpoint to respond with 2xx. This is configurable per-broker if your infrastructure needs more — contact admin.
  • Retries: on non-2xx or timeout, we retry at 5s, 30s, 2min. After 3 failed attempts, the event is abandoned and logged in broker_webhook_logs.
  • Idempotency: every delivery (including retries) carries the same X-AlphaMarket-Event-Id. Use this ID for deduplication.
  • Timestamp: X-AlphaMarket-Timestamp is Unix seconds. Reject requests older than a few minutes to prevent replay.
  • Event type: X-AlphaMarket-Event header carries the event type (e.g. CALL_CREATED) — faster to read than parsing the body.
Tip: accept and acknowledge the webhook (200 OK) before processing the payload asynchronously. This keeps your endpoint fast and prevents retry storms.

6. HMAC signature verification

Each webhook is signed with HMAC-SHA256 over the raw JSON body, using your apiSecret. Always verify signatures before trusting a payload.

Verification — Node.js (Express)

const crypto = require('crypto');
const express = require('express');
const app = express();

const API_SECRET = process.env.ALPHAMARKET_API_SECRET;

// IMPORTANT: use express.raw so the body is a Buffer,
// not already-parsed JSON. HMAC must be over the exact bytes received.
app.post('/alphamarket/webhook',
  express.raw({ type: 'application/json' }),
  (req, res) => {
    const signature = req.headers['x-alphamarket-signature'];
    const expected = crypto
      .createHmac('sha256', API_SECRET)
      .update(req.body)        // req.body is a Buffer here
      .digest('hex');

    if (signature !== expected) {
      return res.status(401).json({ error: 'Invalid signature' });
    }

    const event = req.headers['x-alphamarket-event'];
    const payload = JSON.parse(req.body.toString('utf8'));

    // Process the event — return 200 fast.
    // Heavy work: queue for async processing, don't block the response.
    enqueue(event, payload);

    res.status(200).json({ ok: true });
  }
);

Verification — Python (Flask)

import hmac, hashlib, os, json
from flask import Flask, request, jsonify

API_SECRET = os.environ['ALPHAMARKET_API_SECRET']
app = Flask(__name__)

@app.post('/alphamarket/webhook')
def handle_webhook():
    signature = request.headers.get('X-AlphaMarket-Signature', '')
    raw = request.get_data()  # bytes — verify before parsing
    expected = hmac.new(API_SECRET.encode(), raw, hashlib.sha256).hexdigest()
    if not hmac.compare_digest(signature, expected):
        return jsonify({'error': 'Invalid signature'}), 401

    event = request.headers['X-AlphaMarket-Event']
    payload = json.loads(raw)
    enqueue(event, payload)     # your async processing
    return jsonify({'ok': True}), 200

Common pitfalls:

  • Don't re-serialize JSON before verifying. HMAC is over the raw bytes as received. Serializing req.body after Express parses it changes whitespace and invalidates the signature.
  • Use constant-time comparison (hmac.compare_digest in Python, or compare as equal-length buffers in Node). A simple === is vulnerable to timing attacks.
  • Respond quickly. Do any heavy work (DB writes, pushing to user devices) asynchronously after returning 200.

8. Equity calls (equityCall)

For strategies with strategyType: "Equity" or "Basket", the equityCall field is populated and fnoCall is null.

"equityCall": {
  "exchange": "NSE",
  "legId": "11317",
  "exchangeToken": "2963",
  "symbol": "SAIL",
  "name": "Steel Authority of India Limited",
  "buyDate": "2026-03-14T17:32:38.888Z",
  "buyPrice": 147.0,
  "buyPriceRangeStart": 147.0,
  "buyPriceRangeEnd": 149.0,
  "callType": "BUY",
  "targetPriceRange": "163",
  "profitGoal": "10",
  "stopLoss": "138",
  "status": "PUBLISHED"
}

When the call is closed (target hit, stop triggered, or manually closed), additional fields are populated:

"equityCall": {
  ...same fields as above...
  "sellPrice": 258.2,
  "sellDate": "2025-11-10T08:41:26.365Z",
  "profitLossPercent": 2.257425742574253,
  "exitType": "TargetAchieved",

Mapping to your instrument master

Use exchangeToken — it's the NSE/BSE-native numeric instrument ID. Every Indian broker's instrument master includes this token, so it's a universal join key. Example: SAIL on NSE has exchangeToken: "2963".

If you need to verify a symbol before receiving calls, use the lookup endpoint:

curl -H "x-api-key: $API_KEY" \
  "https://alphamarket.co.in/api/v2/alpha/instruments/lookup?symbol=SAIL&exchange=NSE&type=EQ"

7.5 Webhook payload versions

Your broker account is configured for one of two payload formats. The choice is made by AlphaMarket admin when your broker row is created; switching later is also an admin action (no code change on your end).

v1_flat (default)

Simple, flat JSON. Used by most brokers unless legacy compatibility is required.

{
  "event": "CALL_CREATED",
  "timestamp": "2026-04-18T08:12:35.922Z",
  "data": {
    "uid": "451dfdb8-087f-446a-b60d-2071717222cc",
    "type": "EQUITY",
    "symbol": "HAL",
    "strategyId": "42459575-b915-43d1-bfb1-76140113f772",
    "strategyName": "Equity Short Term",
    "advisorName": "Front Wave Research LLP",
    "action": "Buy",
    "entryPrice": 4370,
    "targetPrice": 4450,
    "stopLoss": 4350,
    "status": "ACTIVE"
  }
}

v1_thealphamarket (Format A)

Byte-exact match to the legacy thealphamarket.com webhook spec. For brokers migrating from the legacy stack, zero code change required on your side.

{
  "status": "success",
  "statusCode": 200,
  "message": {"key": "GET", "message": "Get Successfully"},
  "data": {
    "strategyId": "equity-short-term",
    "theme": ["Equity"],
    "managementStyle": ["Active"],
    "volatility": ["Medium"],
    "horizon": ["Short Term"],
    "strategyName": "Equity Short Term",
    "strategyType": "Equity",
    "advisorName": "Front Wave Research LLP",
    "certificateURl": "/objects/uploads/...",
    "advisorSebiRegistrationNo": "INH000018407",
    "equityCall": {
      "exchange": "NSE",
      "legId": "451df",
      "symbol": "HAL",
      "callType": "BUY",
      "buyPrice": 4370,
      "targetPriceRange": "4450",
      "stopLoss": "4350",
      "status": "PUBLISHED"
    }
  }
}
Format A quirks (preserved from legacy spec for compatibility):
  • rational — note the missing 'e' at the end
  • certificateURl — lowercase 'l' at the end
  • isStoppLossAbsolute — two 'p's (original typo preserved)
  • ISO timestamps use +00:00 suffix, not Z
  • targetPriceRange, stopLoss, profitGoal are sent as strings, not numbers
  • legId is the first 5 hex characters of the call's UUID
Don't "fix" these in your parser — they're intentional for backward compatibility with the old spec.

Which version do I have?

Ask AlphaMarket admin — they'll tell you your broker account's webhook_payload_version setting. It's also reflected in the BrokerScope returned from GET /health.

Back-fill calls from the last 24 hours

curl -X POST \
  -H "x-api-key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "status": "ALL",

    "limit": 500
  }' \
  https://alphamarket.co.in/api/v2/alpha/integration/call/search

Replay missed webhook events

If your webhook endpoint was down for a period, ask AlphaMarket to re-fire the events:

curl -X POST \
  -H "x-api-key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "from": "2026-04-16T10:00:00Z",
    "to":   "2026-04-16T11:00:00Z"
  }' \
  https://alphamarket.co.in/api/v2/alpha/sync/replay

Rate-limited to once per 5 minutes per key.

Check delivery status of recent webhooks

curl -H "x-api-key: $API_KEY" \
  "https://alphamarket.co.in/api/v2/alpha/webhook-logs?delivered=false&limit=50"

Lookup an instrument

curl -H "x-api-key: $API_KEY" \
  "https://alphamarket.co.in/api/v2/alpha/instruments/lookup?symbol=SAIL&exchange=NSE&type=EQ"

13. Testing & UAT

Use the UAT environment (https://uat.alphamarket.co.in/api/v2) for integration testing. AlphaMarket can:

  • Issue a separate UAT API key scoped to test advisors
  • Publish test calls on demand to trigger webhook deliveries
  • Share webhook logs so you can verify delivery and signature

Recommended test sequence for new integrations:

  1. Auth check: GET /health (no key) — confirm 200.
  2. Key check: GET /alpha/advisors — confirm 200 with your scoped advisor list.
  3. Symbol check: GET /alpha/instruments/lookup?symbol=SAIL — confirm exchangeToken: "2963".
  4. Polling check: GET /alpha/live-calls — confirm array of calls, each with equityCall or fnoCall.
  5. Webhook check: Ask AlphaMarket to publish a UAT call. Confirm POST hits your endpoint with valid X-AlphaMarket-Signature.
  6. Lifecycle check: Have AlphaMarket close the UAT call. Confirm CALL_CLOSED and TARGET_ACHIEVED events arrive.
  7. Replay check: POST /alpha/sync/replay for the window — confirm events re-fire.

15. Integration checklist

Quick reference for your integration team during onboarding:

  1. Receive credentials from AlphaMarket admin (via secure channel): api_key + api_secret
  2. Store secrets in environment variables — never in source code or config files committed to git
  3. Verify connectivity: GET /api/v2/health with x-api-key header → expect 200 + your scope info
  4. Test pull API: GET /api/v2/alpha/live-calls?limit=5 → expect scoped results (only advisors/segments you're granted)
  5. If using webhooks:
    • Provide your webhook URL to AlphaMarket admin (must be HTTPS)
    • Confirm your chosen payload version (v1_flat or v1_thealphamarket)
    • Implement HMAC signature verification (see Section 6)
    • Implement idempotency via X-AlphaMarket-Event-Id (see Section 5.3)
    • Test with a webhook.site URL during development before pointing at your real endpoint
  6. Enable IP whitelisting (optional but recommended) before production cutover (Section 2.2)
  7. Monitor: track 4xx/5xx rates, retry counts, webhook delivery latency
  8. Production cutover: coordinate with AlphaMarket support — we'll move your account from sandbox to production scope

Any step failing? Contact hello@alphamarket.co.in with your broker_name + first 16 chars of api_key.
